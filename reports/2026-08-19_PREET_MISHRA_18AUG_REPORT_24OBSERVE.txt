[BUG-001] Validation error envelope is inconsistent

Endpoint:
    POST /api/v1/monitors/

Request:
    {}

Expected:
    HTTP 400
    code = "VALIDATION_FAILED"

Actual:
    HTTP 400
    {
      "error": "body must have required property 'name'"
    }

Actual code:
    None

Assessment:
    LIKELY CONTRACT VIOLATION

Details:
    The API correctly rejects the invalid request with HTTP 400, but the
    response does not contain the stable VALIDATION_FAILED error code expected
    by the test contract.

    Other validation/business-rule errors such as PLAN_INTERVAL_TOO_LOW
    reportedly contain a code, demonstrating that the error envelope is
    inconsistent across validation paths.

Impact:
    Clients cannot reliably identify validation failures programmatically
    using the documented/stable error code.

Recommended fix:
    Return a consistent envelope, for example:

        {
          "code": "VALIDATION_FAILED",
          "error": "body must have required property 'name'"
        }

    Apply the same envelope convention to all request-validation failures.

[BUG-002] Prometheus /metrics endpoint returns 404
------------------------------------------------------------------------------

Endpoint:
    GET /metrics

Expected:
    HTTP 200
    Prometheus exposition format

Actual:
    HTTP 404

OpenAPI metrics-related candidates observed:

    /metrics
    /api/v1/log-metrics/
    /api/v1/log-metrics/{id}
    /api/v1/log-metrics/{id}/series
    /api/v1/otlp/v1/metrics
    /api/v1/metrics/names
    /api/v1/metrics/series
    /api/v1/analyst/metrics

Assessment:
    LIKELY CONTRACT / DOCUMENTATION MISMATCH

Details:
    The test attempted GET /metrics and received 404.

    Before classifying this definitively as an API implementation bug, the
    live OpenAPI definition should be checked for an explicit GET /metrics
    operation and its intended server/base URL.

Recommended fix:
    One of the following should be true:

    A) /metrics is intended to be a public Prometheus endpoint:
       - implement GET /metrics
       - return HTTP 200
       - return Prometheus exposition format

    OR

    B) /metrics is not actually supported:
       - remove it from the documentation/OpenAPI
       - document the correct metrics endpoint instead
